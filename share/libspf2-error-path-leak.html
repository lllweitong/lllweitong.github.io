libspf2 memory leak on the SPF_response_add_error() error path (libspf2 ≤ 1.2.10)

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: libspf2 maintainers
Software: libspf2
Affected version: Current upstream master; the Debian package 1.2.10-8.3 was present in the test environment.
Vulnerable component: SPF_response_add_error() error path; the allocated error buffer is not freed when the SPF_response is destroyed
Vulnerability type: CWE-401 (Missing Release of Memory after Effective Lifetime)
Attack vector: Remote. Each evaluation of a malformed SPF record leaks; the record is published by the sending domain.
CVSS v3.1: 5.3 (Medium) — CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L
Status: LeakSanitizer-confirmed via the SPF interpretation harness over a malformed-record corpus.

Impact. Every malformed SPF evaluation leaks a buffer that is never freed when the response is torn down.

Description

Gradual memory exhaustion in a long-lived process that evaluates SPF over attacker-influenced records. Realistically this needs sustained volume of malformed evaluations to matter, which is why it is rated low, but the input is entirely under the sender's control and no authentication is required.

When libspf2 records an error against an SPF_response it allocates a buffer that the response teardown path does not free. A receiver that evaluates attacker-influenced SPF records therefore leaks a small amount of memory per malformed evaluation, and the growth is unbounded under sustained malformed traffic.

==ERROR== LeakSanitizer: detected memory leaks
  Direct leak of N byte(s) in M object(s) allocated from:
    ... SPF_response_add_error ...

The leak is on the error path specifically, so well-formed records do not trigger it; the attacker needs to induce an SPF evaluation error, which publishing a malformed record achieves.

Proof of Concept

export BUILD="$HOME/asan-build"
bash lib/build_spf.sh          # builds fuzz_spf_compile and fuzz_spf_interp

ASAN_OPTIONS=detect_leaks=1 "$BUILD/fuzz_spf_interp" corpus_spf/
# or a single error-path input:
ASAN_OPTIONS=detect_leaks=1 "$BUILD/fuzz_spf_interp" memory-safety/seeds/L1-spf-leak

Mitigation

Free the error buffer on every SPF_response teardown path.

Notes

A leak only; no corruption, and the lowest severity in this reporting set. Two items are outstanding before vendor contact: re-confirmation against the current libspf2 release, and a minimised single input pinning the exact error term, rather than relying on the corpus.
