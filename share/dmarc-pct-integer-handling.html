DMARC pct integer handling: OpenDMARC wraps modulo 2^32 and Rspamd clamps a negative value to zero (OpenDMARC <= 1.4.2 and Rspamd ≤ 4.1.2)

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: The Trusted Domain Project and the Rspamd project (Vsevolod Stakhov)
Software: OpenDMARC and Rspamd (two distinct defects on the same tag)
Source code: https://github.com/trusteddomainproject/OpenDMARC
Affected version: OpenDMARC 1.4.2 (32-bit unsigned wrap) and Rspamd 4.1.2, originally isolated on 3.10.2 (negative clamp).
Vulnerable component: DMARC pct tag parsing and range check
Vulnerability type: CWE-190 (Integer Overflow or Wraparound) on OpenDMARC; CWE-20 (Improper Input Validation) on Rspamd
Attack vector: Remote. The attacker must be able to influence the victim's published DMARC record; alternatively an administrator's typo produces the same effect.
CVSS v3.1: 5.9 (Medium) — CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:N/I:H/A:N
Status: Reproduced on 2026-07-28 against the current release (run 20260728-120957) with a scripted reproducer, negative controls, and a second independent implementation as the differential oracle. Nine of nine boundary probes deterministic across three repetitions; the modulo-2^32 model fits every observation.

Impact. pct=4294967296 wraps to 0 and re-validates into an enforcing policy on OpenDMARC; pct=-1 disables enforcement on Rspamd.

Description

On OpenDMARC, a pct in the band [2^32, 2^32+100] silently becomes a valid enforcing policy whose sampling rate is not the one written in the record, with no error emitted to the operator. The band at or above 2^31 produces permerror, which disables p=reject altogether.

On Rspamd, any negative pct disables enforcement entirely, so forged mail under a p=reject policy is delivered.

Both directions fail open. The trigger is an administrator typo or an attacker able to influence the published record.

RFC 7489 section 6.3 defines pct as an integer between 0 and 100. Two implementations mishandle values outside that range in different ways.

OpenDMARC parses pct into a 32-bit unsigned integer and only then range-checks it, so the record is accepted exactly when pct mod 2^32 falls in [0, 100]. A value of 2^32 wraps to 0 and re-validates into an enforcing policy; 2^32+50 silently becomes 50 percent sampling.

Rspamd never wraps, but clamps a negative pct to 0, which disables enforcement.

The model “accept if and only if pct mod 2^32 is in [0, 100]” fits all nine probes.

On Rspamd, 2^31, 2^32−1 and 2^64 all produce full DMARC_POLICY_REJECT on forged mail, so there is no wrap. But pct=-1, pct=-100 and pct=-2^31 are clamped to 0, which disables enforcement.

Proof of Concept

# OpenDMARC: an out-of-range value that becomes an enforcing policy with different sampling
_dmarc.victim.example.  IN  TXT  "v=DMARC1; p=reject; pct=4294967296"

# Rspamd: a negative value that disables enforcement
_dmarc.victim.example.  IN  TXT  "v=DMARC1; p=reject; pct=-1"

Send a forged, unaligned message with From: ceo@victim.example. Required in both cases: the value is out of range, so the record is invalid. Observed: OpenDMARC computes 4294967296 mod 2^32 = 0 and applies p=reject with the sampling rate silently changed; Rspamd clamps to 0 and enforces nothing.

Mitigation

Parse pct into a type wide enough to hold the input, or detect overflow during conversion, and reject any value outside 0 to 100 before any modular reduction. On the Rspamd side, reject a negative value rather than clamping it. Neither implementation should silently substitute a different sampling rate for the one published.

Notes

The “at or above 2^31 yields permerror yields fail-open” half overlaps opendmarc-bad-tag-drops-policy, which already lists an out-of-range pct as a permerror trigger. What is new here is the 32-bit truncation model with its wrap-into-range hole — an out-of-range value producing an enforcing policy, the opposite of a permerror — and the Rspamd negative clamp, which is on a different implementation entirely.
