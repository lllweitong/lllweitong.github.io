dkimpy unhandled IndexError in rfc822_parse() on a message beginning with whitespace (dkimpy ≤ 1.1.8)

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: dkimpy maintainers (Scott Kitterman et al.)
Software: dkimpy
Source code: https://launchpad.net/dkimpy
Affected version: dkimpy 1.1.8 (the version tested); the parsing code is long-standing and earlier releases are expected to be affected.
Vulnerable component: dkim/__init__.py, rfc822_parse(), line 372
Vulnerability type: CWE-248 (Uncaught Exception)
Attack vector: Remote, unauthenticated. One inbound e-mail whose first byte is a space or tab.
CVSS v3.1: 7.5 (High) — CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H
Status: Confirmed with a two-byte proof of concept under coverage-guided fuzzing.

Impact. A two-byte message whose first line starts with a space or tab raises an uncaught IndexError out of dkim.DKIM().verify().

Description

Any application that feeds untrusted message bytes to dkim.DKIM() or dkim.verify() and catches only DKIMException, as the documentation instructs, crashes on an attacker-supplied message beginning with a space. In a mail filter that means a processing failure per message, and in a single-threaded filter a service outage; the practical severity depends on how the calling application handles an unexpected exception.

dkimpy is used by authheaders and by a number of Python mail filters, so the exposure is wider than direct users of the library.

rfc822_parse() appends a header continuation line to the previous header with headers[-1][1] += .... When the very first line of the message begins with whitespace there is no previous header, headers is still empty, and the indexing raises IndexError. The exception is not caught and not converted to the library's own DKIMException, so it propagates out of DKIM.verify().

This matters because the documented contract tells callers to catch DKIMException. An application that follows the documentation will not catch IndexError and will crash.

The message need not be valid, signed, or even syntactically plausible. Any input whose first byte is a space or tab reaches the defect, because a leading whitespace character is interpreted as a header-folding continuation of a header that does not exist.

>>> import dkim
>>> dkim.DKIM(b" \r\n").verify(dnsfunc=lambda n, **k: b"")
Traceback (most recent call last):
  ...
  File ".../dkim/__init__.py", line 372, in rfc822_parse
    headers[-1][1] += line
IndexError: list index out of range

Proof of Concept

import dkim

dkim.DKIM(b" \r\n").verify(dnsfunc=lambda n, **k: b"")   # IndexError
dkim.DKIM(b"\tx\r\n").verify(dnsfunc=lambda n, **k: b"")  # IndexError

Two bytes are sufficient. Both a space and a tab trigger it.

Mitigation

Treat a continuation line with no preceding header as a malformed message rather than indexing an empty list:

if line[0] in b' \t':
    if not headers:
        raise MessageFormatError("continuation line before any header")
    headers[-1][1] += line

Raising the library's own exception type keeps the documented contract intact. Silently ignoring the stray line is the alternative if bug-compatibility with permissive parsers is preferred.
