OpenDMARC one-byte stack-buffer underflow in opendmarc_util_finddomain() (OpenDMARC ≤ 1.4.2)

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: The Trusted Domain Project
Software: OpenDMARC (libopendmarc)
Source code: https://github.com/trusteddomainproject/OpenDMARC
Affected version: OpenDMARC 1.4.2 and earlier, and current upstream master (commit bf37d53).
Vulnerable component: libopendmarc/opendmarc_util.c, opendmarc_util_finddomain() line 278, called from opendmarc_policy_store_from_domain()
Vulnerability type: CWE-125 (Out-of-bounds Read)
Attack vector: Remote in the library. In the shipped milter the From parser guards this vector, so direct remote reachability is not established.
CVSS v3.1: 4.8 (Medium) — CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:L/I:N/A:L
Status: AddressSanitizer-confirmed in the library with a two-byte proof of concept. Not demonstrated through the shipped milter.

Impact. A From header that normalises to the empty string makes the domain finder read one byte before its stack array.

Description

A single-byte read before a stack array. On a normal build it reads an adjacent stack byte and usually does not fault; under AddressSanitizer, a hardened allocator, or an unlucky stack layout it faults, giving a denial of service. It is undefined behaviour in every case.

opendmarc_util_finddomain() copies the From value into a stack buffer and normalises it by stripping quotes and truncating at an unquoted comma. If that normalisation empties the buffer, the following backwards scan for < starts at copy - 1, its loop condition b > copy is false immediately, and the post-loop if (*b == '<') reads one byte before the array.

u_char copy[BUFSIZ];
...
for (cp = copy; *cp != '\0'; ++cp)
{
    ...
    if (numquotes == 0 && *cp == ',')   /* empties copy when the comma is first */
    {
        *cp = '\0';
        break;
    }
    ...
}
ep = copy + strlen((char *) copy);      /* ep == copy when copy is now "" */
for (b = ep - 1; b > copy; --b)         /* b = copy - 1; the body never runs */
{
    if (*b == '<')
        break;
}
if (*b == '<')                          /* line 278 - dereferences copy[-1] */
==ERROR== AddressSanitizer: stack-buffer-underflow
READ of size 1 at 0x... offset 31
    ... underflows this variable 'copy'
    #0 opendmarc_util_finddomain opendmarc_util.c:278

The caller's only guard is strlen(from_domain) == 0 in opendmarc_policy_store_from_domain(). That rejects an input that is already empty, but not a non-empty input such as "," that becomes empty inside finddomain.

Proof of Concept

The harness input format is <dmarc-record>\0<from-domain>. The minimal trigger is two bytes: an empty record and a From domain of ,.

printf '\0,' > pocA
./fuzz_odmarc_record pocA
==ERROR== AddressSanitizer: stack-buffer-underflow ... READ of size 1
          ... in opendmarc_util_finddomain opendmarc_util.c:278

The equivalent library-level input is a From value of ,, or any value that the comment- and quote-stripping reduces to the empty string.

Mitigation

 ep = copy + strlen((char *) copy);
 b = ep - 1;
 for (; b > copy; --b)
 {
     if (*b == '<')
         break;
 }
-if (*b == '<')
+if (b >= copy && *b == '<')     /* or: if (ep > copy && *b == '<') */

Do not dereference b when the working buffer is empty.

Notes

Honest scoping. This is confirmed in libopendmarc through the direct library entry point. The milter's own From parser guards the vector before this function is reached, so a remotely delivered message was not shown to reach it. The finding is therefore best treated as a library-level defect affecting third-party consumers of libopendmarc, with the milter path unproven. Rated accordingly.
