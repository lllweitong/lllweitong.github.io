OpenARC memory leak in arc_canon_runheaders(): the dynamic string allocated for canonicalisation is never freed (OpenARC (master))

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: The Trusted Domain Project
Software: OpenARC (libopenarc)
Source code: https://github.com/trusteddomainproject/OpenARC
Affected version: Current upstream master.
Vulnerable component: libopenarc/arc-canon.c, arc_canon_runheaders(); the allocation from arc_dstring_new() is not released by arc_free()
Vulnerability type: CWE-401 (Missing Release of Memory after Effective Lifetime)
Attack vector: Remote. Leaks once per ARC-verified message; forwarded mail carries ARC chains by design.
CVSS v3.1: 5.3 (Medium) — CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L
Status: LeakSanitizer-confirmed.

Impact. Every ARC-verified message leaks a dynamic string, so memory grows in proportion to forwarded-mail volume.

Description

Unbounded memory growth in a long-lived OpenARC verifier that processes forwarded mail, ending in resource exhaustion. It is slow and requires sustained volume, so it is the least severe finding in this set, but it needs no malformed input at all: legitimate traffic alone drives it.

A dynamic string allocated during header canonicalisation in arc_canon_runheaders() is never released, and arc_free() does not reclaim it. Because canonicalisation runs for every ARC-verified message, the leak is steady and proportional to the volume of forwarded mail the verifier handles.

LeakSanitizer reports a definite leak rooted at the allocation:

==ERROR== LeakSanitizer: detected memory leaks
  Direct leak of N byte(s) in M object(s) allocated from:
    ... arc_dstring_new <- arc_canon_runheaders ...

There is no malformed-input precondition. Any well-formed ARC instance that completes header canonicalisation leaks the string, so ordinary legitimate forwarded mail drives the growth.

Proof of Concept

export BUILD="$HOME/asan-build"
bash lib/build_openarc.sh
ASAN_OPTIONS=detect_leaks=1 "$BUILD/fuzz_openarc" memory-safety/seeds/C7-arc-crash

# run over a corpus of well-formed ARC messages to show steady per-message growth
ASAN_OPTIONS=detect_leaks=1 "$BUILD/fuzz_openarc" corpus_arc/

Mitigation

Free the arc_dstring in arc_free(), or release it at the end of canonicalisation once it is no longer needed.

Notes

Pairs with the null-pointer dereference openarc-c-tag-null-deref in the same ARC and forwarding code path, which appears less exercised than the equivalent DKIM path. Re-confirmation against the current OpenARC release is outstanding.
