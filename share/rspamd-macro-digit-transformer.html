Rspamd ignores the digit transformer in SPF macro expansion, so a mechanism built from %{d2} queries the untruncated domain (Rspamd ≤ 4.1.2)

Author: Weitong Li, Virginia Tech <weitongli@vt.edu>
Date: 2026-07-31
Vendor: Rspamd project (Vsevolod Stakhov)
Software: Rspamd
Source code: https://github.com/rspamd/rspamd
Affected version: Rspamd 4.1.2. Originally isolated on 3.10.2 and re-confirmed on 4.1.2 on 2026-07-28.
Vulnerable component: SPF module — macro expansion, specifically the transformer digit in %{dN} and %{oN}
Vulnerability type: CWE-20 (Improper Input Validation)
Attack vector: Remote. No attacker action is required: any sender whose published record uses a digit transformer is evaluated against the wrong name on every Rspamd receiver.
CVSS v3.1: 4.8 (Medium) — CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:N/I:L/A:L
Status: Reproduced on 2026-07-28 against the current release (run 20260728-120957) with a scripted reproducer, negative controls, and a second independent implementation as the differential oracle. A DNS-toggle experiment publishing the A record at exactly one of the two candidate names, with %{d} and %{dr} as consensus controls, re-verified on a second host.

Impact. A record written with exists:%{d2}.k.probe.example.com is evaluated by Rspamd against the full sender domain rather than its rightmost two labels, so the mechanism matches on the wrong DNS name or not at all.

Description

A domain's published SPF policy does not evaluate as authored on Rspamd receivers. Digit transformers appear in real records: they are the idiomatic way to reference an organisational domain from a subdomain sender, and large senders use them for per-tenant and per-address-range exists: patterns.

The usual direction is fail-closed. The intended name is not queried, the mechanism does not match, evaluation falls through to the record's terminal -all, and a legitimate sender's aligned mail is marked spf=fail and can fail DMARC under the sender's own policy. The fail-open direction exists but is conditional: if a record happens to exist at the untruncated name — a wildcard under the probe zone, or a name published for another purpose — then a mechanism that should not have matched does match, and an unintended host is authorised. That requires the untruncated name to exist by coincidence or by an attacker's arrangement, so it is a narrower case than the fail-closed one.

Either way the record author's intent is not what is enforced, and the same record produces different verdicts on Rspamd and on conforming verifiers.

RFC 7208 section 7.3 specifies that a digit in a macro transformer gives the number of rightmost labels to keep after expansion. On a sender domain of m.n.o.example.com, %{d2} must expand to example.com.

Rspamd parses the macro but drops the digit and expands to the full domain. Every DNS-querying mechanism built from %{dN} — exists:, a:, mx:, include: — therefore queries a name the record author never wrote, and the mechanism does not match where it was intended to.

The experiment is a DNS toggle, which removes any dependence on the connecting address: exists: matches on the existence of a name, so publishing the A record at exactly one of the two candidate names reveals which name was queried. The sender is m.n.o.example.com and the record is v=spf1 exists:%{d2}.k.probe.example.com -all, so a conforming expansion of %{d2} is example.com:

example.com.k.probe.example.com (rightmost two labels, the conforming name)spf=passR_SPF_FAILOpenDMARC expanded %{d2} to example.com; Rspamd never queried that name

The two rows are mutually exclusive and between them pin the expansion exactly. Only one name exists at a time, and each verifier passes precisely when the name it queried is the one that exists.

Controls isolate the digit as the sole cause. %{d} with no transformer and %{dr} with the reverse transformer are both consensus: Rspamd applies reversal and delimiter splitting correctly, and only the truncation digit is lost. The divergence generalises to %{d3} and %{d4}, and to %{o2} on the MAIL FROM domain, so it is a property of the transformer parser rather than of one macro letter.

A five-label sender name was used deliberately so that the laboratory's example.com-as-public-suffix fixture plays no part in the result: the truncation under test removes three labels and is unrelated to any organisational-domain computation.

Proof of Concept

Publish, for a sender domain of five labels, a record whose only querying term uses a digit transformer, and place the A record at the conforming name only:

m.n.o.example.com.                      IN TXT "v=spf1 exists:%{d2}.k.probe.example.com -all"
example.com.k.probe.example.com.        IN A   192.0.2.1
; and deliberately nothing at m.n.o.example.com.k.probe.example.com

Send from any public address:

MAIL FROM:<alice@m.n.o.example.com>
RCPT TO:<user@receiver.test>

Required under RFC 7208 section 7.3: %{d2} expands to example.com, the name example.com.k.probe.example.com exists, the exists: mechanism matches and the result is pass. Observed on Rspamd: R_SPF_FAIL, because it queried m.n.o.example.com.k.probe.example.com, which does not exist. OpenDMARC's SPFSelfValidate on the identical setup returns spf=pass.

Inverting the toggle completes the proof. Publish the A record at the untruncated name instead, and Rspamd returns R_SPF_ALLOW while OpenDMARC returns spf=fail.

Mitigation

Apply the transformer digit in the macro expander: after expanding the macro letter and splitting on the delimiter set, keep only the specified number of rightmost fields, per RFC 7208 section 7.3. The reversal and delimiter handling in the same expander are already correct, so the digit needs to be applied at the same point rather than parsed and discarded.

Notes

Distinct from the other SPF findings in this series. It is not a multi-record selection defect and not a temporary-error mapping defect; it sits in the macro transformer layer, which had not been exercised beyond plain %{d} and %{o}.

The result is independent of the connecting address by construction, because exists: matches on name existence alone.
